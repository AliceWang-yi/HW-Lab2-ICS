## `defuser.c` 说明

**一关一个函数：**

```c
int solve_phase_1(uint64_t challenge, char *out, size_t cap) {
    // 用 challenge 算出这一关的口令，写进 out
    return 0;   // 做好了；还没做就 return 1
}
```

- 输入只有一个：`challenge`，一个 64 位数，就是这一关的题目，每次运行都不一样。
- 你的任务：用它算出口令，写进 `out`。
- 做好了 `return 0`；还没做 `return 1`，测试会显示 not attempted。

**口令介绍：** 前六关都是一行十进制整数、用空格隔开，比如 `1234 5678 90`。要几个数得自己从汇编里数出来，炸弹不会提示。每个整数都是 32 位无符号数。

模板已经把一半的活儿干好了：把每个整数填进 `values[]`，把 `count` 改成整数个数，`write_answer` 会自动拼成一行。`count` 留着 0 就是"还没做"。

**输出格式要求：**

- 只有一行，非空，结尾是 `'\0'`，中间不能有换行。
- 调试信息用 `fprintf(stderr, ...)` 输出。用 `printf` 会把口令弄脏，直接判格式错误。
- 整行最多 254 字节（测试按 stdout 算，含驱动补的换行不能到 256）。

**一些提示：**

- **答案不能写死。** challenge 每次都不同，评分用的是你没见过的 challenge，所以你要交出的是"怎么算"的公式，不是某一次的答案。
- **`seed` 不用你管。** 驱动已经用和炸弹一样的方法把 seed 换算成 challenge 传给你了。
- 编译开了 `-Werror`，有警告就编不过。

**别让"还没做"掐断后面的关。** 未完成的关先 `return 1` 是模板给的占位写法，本身不扣分；但**只要有一关返回非 0，驱动就当场停下，后面所有关的口令一行都不会输出**。

- 想单独调某一关，用 `./defuser --seed 42 --phase 5`，前面没做的关不会挡路。
- 不要用 `./defuser --seed 42 | ./bomb --seed 42` 去试后面的关，前面的 TODO 一挡就什么都看不到。

**第七行（选做 Honor）。** `solve_secret(challenge, context, out, cap)` 多给一个 `context`。第七行格式随便，一行文本就行，不限于整数。不做就一直 `return 1`，公开测试显示 not attempted 并通过，不影响正式六关的分数。
